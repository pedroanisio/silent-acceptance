Silent Acceptance

LLM Output Error as an Architectural Invariant

Versions 1.x were published as PALS's Law under the same concept DOI.

↓ GitHub DOI · Zenodo Linter · CI check

Silent acceptance is the defect in which a system passes LLM output to a downstream consumer with no declared verification boundary.

Across any realistic deployment, LLMs reliably produce errors — at a rate that is non-zero and non-negligible. Failing to verify LLM output is not a bug in the generated artifact. It is an architectural omission in the system that consumed it.

Passing LLM output onward with no declared verification boundary is a design defect, regardless of how correct the output appears to be.

The Operative Claim

For every autoregressive transformer language model and every realistic task distribution, the expected error rate is bounded below by a non-negligible constant:

The value of δ is task- and model-dependent but is never zero. Published benchmarks place it well above machine-epsilon for every model tested to date. No individual call is guaranteed to fail; the distribution over calls guarantees failure at scale.

Nine Error Classes

Each class requires a distinct detection strategy. No single verifier can detect all classes — which is why a verification boundary is declared per class, not as a single bit.

The Capability-Detection Asymmetry

The specification's one original and testable claim, stated as a labeled hypothesis with an experiment protocol: as model capability C grows, the errors that remain migrate toward the classes that are hardest to detect. With detection difficulty Dc defined as the miss rate of a fixed verifier on class c,

A less capable model fabricates a citation with a nonsensical author and a malformed DOI. A more capable model fabricates one with a real author, a real journal, and a plausible abstract. The verifier that caught the first is blind to the second — so a verifier held constant across a model upgrade is a regression, not a conservative default.

The Verification Boundary Principle

Every system that consumes LLM output must declare a verification boundary before the output reaches a consumer: which error classes are checked (scope), by what (mechanism), against which model version (calibration), and where the verifier runs and who cannot modify it (location). Six corollaries follow.

Corollary 1 · Appearance ≠ Correctness

Manual review during development does not substitute for runtime verification in production.

Corollary 2 · Trust Accumulation Prohibited

A system must not relax its verification boundary after observing a run of correct outputs.

Corollary 3 · Verification Scope = Error Taxonomy

Verification claims must be scoped and documented — a schema validator does not cover hallucination.

Corollary 4 · Silent Acceptance is a Defect

Absence of a declared boundary is a blocking defect, equivalent to missing authentication. The check is mechanical and automated.

Corollary 5 · Verifier Upgrade Precedes Model Upgrade

If the asymmetry holds, a boundary calibrated on the old model is blind exactly where the new model's residual errors concentrate.

Corollary 6 · The Verifier Sits Outside the Boundary

A verifier the model or its agent can edit inherits the model's error distribution and is under pressure to weaken the check. Harness-tampering audits find exactly that. A verifier the agent can rewrite is silent acceptance with extra steps.

Quick Start

Inline banner

// ⚠ VERIFICATION BOUNDARY: LLM output is untrusted by default. Verify before use. (Silent Acceptance v2.0.0)

Contract block (TypeScript)

/**
 * ⚠ VERIFICATION BOUNDARY — Silent Acceptance specification
 * SILENT_ACCEPTANCE_VERSION: 2.0.0
 * MODEL_VERSION: <pinned model>
 * VERIFIER_LOCATION: <module the model cannot write to>
 *
 * ERROR CLASSES NOT COVERED BY THIS BOUNDARY:
 *   [ ] ERR_HALLUCINATION
 *   [ ] ERR_OMISSION
 *   [ ] ERR_SCHEMA
 *   [ ] ERR_TRUNCATION
 *   [ ] ERR_SYCOPHANCY
 *   [ ] ERR_INSTRUCTION
 *   [ ] ERR_CALIBRATION
 *   [ ] ERR_SEMANTIC
 *   [ ] ERR_REASONING
 *
 * MITIGATION: <downstream boundary or accepted-risk note per unchecked class>
 */

Foundations and Evidence

The inevitability of LLM hallucination has been independently established by:

Kalai & Vempala (STOC 2024) — statistical lower bound for calibrated language models, tied to the monofact rate. DOI

Xu, Jain & Kankanhalli (2024) — computability-theoretic diagonalization proof. arXiv

Karpowicz (2025) — impossibility via mechanism design theory. arXiv

The harness-level evidence behind Corollary 6:

Lewis (2026) — same model, same tasks, one context-policy change in the harness: fail-to-pass fraction moved from 28 to 49 percent. arXiv

Wang, Zhang & Shao (2026) — self-improving agents tamper with their own harness, and the tampered edits persist in the best lineage. arXiv

Guo et al. (2026) — self-authored verification scores stay near perfect while sealed deployment performance degrades; at least one acceptance signal outside the agent's control is required. arXiv

The specification does not claim priority over these results. Its contribution is the bridge from theoretical inevitability to an enforceable engineering contract, and the check that enforces it.
