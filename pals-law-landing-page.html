PALS's Law

A Formal Specification of LLM Output Unreliability as an Architectural Invariant

↓ GitHub DOI · Zenodo arXiv preprint

Across any realistic deployment, LLMs reliably produce errors — at a rate that is non-zero and non-negligible.

Failing to verify LLM output is not a bug in the generated artifact. It is an architectural omission in the system that consumed it.

Absence of a verification layer is a design defect, regardless of how correct the LLM output appears to be.

The Operative Claim

For every autoregressive transformer language model and every realistic task distribution, the expected error rate is bounded below by a non-negligible constant:

The value of δ is task- and model-dependent but is never zero. Published benchmarks place it well above machine-epsilon for every model tested to date. No individual call is guaranteed to fail; the distribution over calls guarantees failure at scale.

Nine Error Classes

Each class requires a distinct detection strategy. No single verifier can detect all classes — this is the foundational motivation for treating verification as a first-class architectural concern.

Five Corollaries

Corollary 1 · Appearance ≠ Correctness

Manual review during development does not substitute for runtime verification in production.

Corollary 2 · Trust Accumulation Prohibited

A system must not relax its verification layer after observing a run of correct outputs.

Corollary 3 · Verification Scope = Error Taxonomy

Verification claims must be scoped and documented — a schema validator does not cover hallucination.

Corollary 4 · Silent Acceptance is a Defect

Absence of an output validation layer is a blocking defect, equivalent to missing authentication.

Corollary 5 · Capability Growth Shifts Risk

More capable models produce harder-to-detect errors. Verifier upgrades are a precondition for model upgrades.

Theoretical Foundations

The inevitability of LLM hallucination has been independently established by:

Kalai & Vempala (STOC 2024) — statistical lower bound for calibrated language models, tied to the monofact rate. DOI

Xu, Jain & Kankanhalli (2024) — computability-theoretic diagonalization proof. arXiv

Karpowicz (2025) — impossibility via mechanism design theory. arXiv

PALS's Law does not claim priority over these results. Its contribution is the bridge from theoretical inevitability to an enforceable engineering contract.
